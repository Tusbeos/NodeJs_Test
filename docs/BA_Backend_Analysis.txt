- **Authentication:** Spring Security 6 + JWT (jjwt library)
- **Email Service:** Spring Mail (spring-boot-starter-mail)

## 2. Phân tích Entities & Relationships

### Core Entities
- **User (users):** Đa vai trò (Admin, Doctor, Patient), thông tin cơ bản, metadata, roleId, positionId
- **DoctorInfo (doctor_infos):** Thông tin chuyên môn bác sĩ, priceId, provinceId, paymentId, nameClinic, addressClinic, note, doctorId, clinicId
- **Doctor_Clinic_Specialty:** Bảng liên kết N-N-N (Doctor ↔ Clinic ↔ Specialty), unique composite index
- **Schedule (schedules):** Quản lý lịch khám theo ngày và khung giờ, doctorId, date, timeType, maxNumber, currentNumber
- **Booking (bookings):** Quản lý đặt lịch hẹn, status workflow, token, birthday, reason, date, timeType, doctorId, patientId, statusId
- **Specialty (specialties) & Clinic (clinics):** Thông tin chuyên khoa và phòng khám, markdown content
- **AllCode (allCodes):** Master data table quản lý danh mục chung (ROLE, GENDER, POSITION, TIME, PRICE, PAYMENT, PROVINCE, STATUS)

### Entity Relationships
- **User** có quan hệ 1-N với **Booking** (1 user có nhiều bookings)
- **Doctor** có quan hệ 1-N với **Schedule** (1 bác sĩ có nhiều lịch khám)
- **Doctor** có quan hệ N-N-N với **Clinic** và **Specialty** qua bảng **Doctor_Clinic_Specialty**
- **Booking** liên kết với **User** (patientId), **Doctor** (doctorId), và **AllCode** (statusId, timeType)
- **AllCode** được sử dụng làm master data cho tất cả các enum/lookup values

## 3. Phân tích Business Logic theo Module

### 3.1 Authentication & User Management
**Chức năng chính:**
- Login với email/password + bcrypt verification
- CRUD Users (Create, Read, Update, Delete)
- Validation: email uniqueness check
- Password hashing tự động khi tạo user

**Vấn đề hiện tại:**
- Chưa có JWT token authentication
- Không có password reset mechanism
- Thiếu RBAC (Role-Based Access Control) middleware

**Đề xuất cải tiến:**
- ✅ Implement JWT token-based authentication
- ✅ Thêm password reset flow (email verification)
- ✅ RBAC middleware để phân quyền Admin/Doctor/Patient

---

### 3.2 Doctor Management
**Chức năng chính:**
- Lưu thông tin bác sĩ: Upsert Markdown, DoctorInfo, Doctor_Clinic_Specialty
- Quản lý lịch khám: Normalize date, xóa/giữ/upsert khung giờ
- Liên kết bác sĩ với chuyên khoa và phòng khám

**Vấn đề hiện tại:**
- Không sử dụng database transaction (có thể dẫn đến dữ liệu không nhất quán)
- Thiếu validation cho maxNumber, duplicate schedules
- Không kiểm tra xung đột lịch khám

**Đề xuất cải tiến:**
- ✅ Wrap tất cả operations trong transaction
- ✅ Validate maxNumber > currentNumber
- ✅ Prevent duplicate schedules (doctorId + date + timeType unique)
- ✅ Check schedule conflicts trước khi upsert

---

### 3.3 Booking & Patient Management
**Chức năng chính:**
- Đặt lịch khám: Validate fields, generate UUID token, gửi email xác nhận
- Auto-create user nếu email chưa tồn tại
- Kiểm tra slot còn trống (currentNumber < maxNumber)
- Email Verification: Update status từ S1 (Pending) → S2 (Confirmed)

**Vấn đề hiện tại:**
- Race condition khi nhiều người book cùng 1 slot
- Token verification không có expiration time
- Không có resend email mechanism
- Thiếu validate doctorId, date, timeType hợp lệ

**Đề xuất cải tiến:**
- ✅ Use transaction + row-level locking để tránh race condition
- ✅ Thêm token expiration (1 hour)
- ✅ Implement resend email API
- ✅ Validate doctorId exists, date >= today, timeType valid

---

### 3.4 Specialty & Clinic Management
**Chức năng chính:**
- CRUD với image upload (base64 encoding)
- Markdown editor cho description
- Lọc bác sĩ theo specialty/clinic

**Vấn đề hiện tại:**
- Base64 encoding làm database size lớn
- Không cleanup orphan records khi xóa
- Thiếu soft delete mechanism

**Đề xuất cải tiến:**
- ✅ Sử dụng S3/Cloudinary thay vì base64
- ✅ Cleanup orphan Doctor_Clinic_Specialty records
- ✅ Implement soft delete (thêm field deletedAt)

## 4. Phân tích Database Schema

### Điểm mạnh:
- ✅ **AllCode pattern:** Giảm redundancy, dễ maintain master data
- ✅ **Composite unique index:** Trên Doctor_Clinic_Specialty (doctorId, clinicId, specialtyId) ngăn duplicate
- ✅ **Normalized design:** Tách biệt User, DoctorInfo, Markdown

### Điểm yếu:
- ⚠️ Thiếu index cho các query phổ biến (email, doctorId, date)
- ⚠️ Thiếu audit fields (createdAt, updatedAt, deletedAt)
- ⚠️ Date field lưu dạng STRING thay vì DATE/BIGINT

### Đề xuất cải tiến:
```sql
-- Thêm indexes
ALTER TABLE users ADD INDEX idx_email (email);
ALTER TABLE bookings ADD INDEX idx_doctor_date (doctorId, date);
ALTER TABLE schedules ADD INDEX idx_doctor_date_time (doctorId, date, timeType);

-- Thêm audit fields
ALTER TABLE bookings ADD deletedAt DATETIME NULL;
ALTER TABLE doctor_infos ADD createdBy INT NULL;
```

## 5. Security Issues

### Vấn đề hiện tại (Node.js):
- ❌ **No authentication middleware:** API endpoints không kiểm tra token
- ❌ **Input sanitization:** Dễ bị XSS, SQL Injection
- ❌ **Rate limiting:** API không giới hạn số request
- ❌ **CORS config:** Quá loose, chấp nhận tất cả origins
- ❌ **Base64 image storage:** Không giới hạn file size, có thể bị DOS attack
- ❌ **Password validation:** Không có rules (min length, complexity)

### Đề xuất cải tiến (Node.js):
```javascript
// 1. JWT Middleware
const verifyToken = (req, res, next) => {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ message: 'Unauthorized' });
  jwt.verify(token, process.env.JWT_SECRET, (err, decoded) => {
    if (err) return res.status(403).json({ message: 'Forbidden' });
    req.user = decoded;
    next();
  });
};
```

### Giải pháp với Spring Boot (Tốt hơn):

**1. Spring Security + JWT Configuration:**
```java
// security/SecurityConfig.java
@Configuration
@EnableWebSecurity
@EnableMethodSecurity
public class SecurityConfig {
    
    @Autowired
    private JwtAuthenticationEntryPoint unauthorizedHandler;
    
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())
            .cors(cors -> cors.configurationSource(corsConfigurationSource()))
            .exceptionHandling(ex -> ex.authenticationEntryPoint(unauthorizedHandler))
            .sessionManagement(session -> 
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                // Public endpoints
                .requestMatchers("/api/auth/**", "/api/public/**").permitAll()
                .requestMatchers("/swagger-ui/**", "/v3/api-docs/**").permitAll()
                
                // Role-based access
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .requestMatchers("/api/doctor/**").hasAnyRole("DOCTOR", "ADMIN")
                .requestMatchers("/api/patient/**").hasAnyRole("PATIENT", "ADMIN")
                
                // Authenticated
                .anyRequest().authenticated()
            )
            .addFilterBefore(jwtAuthenticationFilter(), 
                           UsernamePasswordAuthenticationFilter.class);
        
        return http.build();
    }
    
    @Bean
    public CorsConfigurationSource corsConfigurationSource() {
        CorsConfiguration configuration = new CorsConfiguration();
        configuration.setAllowedOrigins(Arrays.asList(
            "http://localhost:3000",
            "https://yourdomain.com"
        ));
        configuration.setAllowedMethods(Arrays.asList("GET", "POST", "PUT", "DELETE", "OPTIONS"));
        configuration.setAllowedHeaders(Arrays.asList("*"));
        configuration.setAllowCredentials(true);
        
        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/api/**", configuration);
        return source;
    }
    
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder(10);
    }
}
```

**3. Rate Limiting với Bucket4j:**
```java
// config/RateLimitConfig.java
@Configuration
public class RateLimitConfig {
    
    @Bean
    public Bucket createBucket() {
        Bandwidth limit = Bandwidth.classic(100, Refill.intervally(100, Duration.ofMinutes(15)));
        return Bucket.builder()
            .addLimit(limit)
            .build();
    }
}

// filter/RateLimitFilter.java
@Component
public class RateLimitFilter extends OncePerRequestFilter {
    
    @Autowired
    private Bucket bucket;
    
    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, IOException {
        if (bucket.tryConsume(1)) {
            filterChain.doFilter(request, response);
        } else {
            response.setStatus(429);
            response.getWriter().write("{\"error\": \"Too many requests\"}");
        }
    }
}
```

```java
public class XssConfig {
    
    @Bean
    public FilterRegistrationBean<XssFilter> xssFilter() {
        FilterRegistrationBean<XssFilter> registrationBean = new FilterRegistrationBean<>();
        registrationBean.setFilter(new XssFilter());
        registrationBean.addUrlPatterns("/api/*");
        return registrationBean;
    }
}

// filter/XssFilter.java
public class XssFilter implements Filter {
    @Override
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain) {
        XssRequestWrapper wrappedRequest = new XssRequestWrapper((HttpServletRequest) request);
        chain.doFilter(wrappedRequest, response);
    }
}
```

## 6. Performance Bottlenecks

### Vấn đề hiện tại:
- ⚡ **N+1 Query Problem:** Khi lấy danh sách doctor kèm specialty/clinic
- ⚡ **Image encoding overhead:** Base64 encode/decode làm chậm response
- ⚡ **No caching:** Mỗi request đều query database
- ⚡ **No pagination:** Trả toàn bộ records có thể quá lớn

### Đề xuất cải tiến:
```javascript
// 1. Eager Loading (Sequelize)
const doctors = await User.findAll({
  where: { roleId: 'R2' },
  include: [
    { model: DoctorInfo, as: 'doctorData' },
    { model: Specialty, as: 'specialties', through: { attributes: [] } }
  ],
  raw: false // IMPORTANT: avoid nested objects
});

// 2. Redis Cache
const redis = require('redis');
const client = redis.createClient();

app.get('/api/specialties', async (req, res) => {
  const cacheKey = 'specialties:all';
  const cached = await client.get(cacheKey);
  if (cached) return res.json(JSON.parse(cached));
  
  const data = await Specialty.findAll();
  await client.setEx(cacheKey, 3600, JSON.stringify(data)); // cache 1 hour
  res.json(data);
});

// 3. Pagination
app.get('/api/doctors', async (req, res) => {
  const { page = 1, limit = 10 } = req.query;
  const offset = (page - 1) * limit;
  
  const { count, rows } = await User.findAndCountAll({
    where: { roleId: 'R2' },
    limit: parseInt(limit),
    offset: parseInt(offset)
  });
  
  res.json({ total: count, page, data: rows });
});
```

## 11. Kết luận & Roadmap

### A. Điểm mạnh của hệ thống hiện tại:
- ✅ **Kiến trúc MVC rõ ràng:** Tách biệt Controller → Service → Model
- ✅ **Sequelize ORM đầy đủ:** Associations (hasMany, belongsTo, belongsToMany)
- ✅ **AllCode pattern:** Master data management linh hoạt
- ✅ **Support N-N-N relationship:** `doctor_clinic_specialty` junction table
- ✅ **Email verification:** Token-based confirmation flow (S1 → S2)

### B. Critical Improvements (Cần cải thiện ngay):

**1. Security & Authentication:**
- ⚠️ Chưa có JWT token authentication
- ⚠️ Password chưa hash đủ mạnh (cần bcryptjs với salt rounds >= 10)
- ⚠️ Thiếu RBAC middleware (role-based access control)
- ⚠️ CORS chưa config đúng cho production

**2. Input Validation:**
- ⚠️ Thiếu Joi/Yup schema validation
- ⚠️ SQL Injection risk (dù dùng Sequelize vẫn cần sanitize)
- ⚠️ XSS protection chưa đủ

**3. Business Logic:**
- ⚠️ Thiếu transaction management (booking + schedule update phải atomic)
- ⚠️ Race condition khi booking cùng 1 slot
- ⚠️ Thiếu rate limiting cho API

**4. Performance:**
- ⚠️ N+1 query problem (cần eager loading)
- ⚠️ Thiếu Redis cache
- ⚠️ Không có pagination

### C. Roadmap triển khai:

#### A. AllCode Pattern → Enum + JPA
**Vấn đề:** AllCode table lưu master data dạng key-value (ROLE, STATUS, TIME, v.v.)

**Giải pháp 1: Chuyển sang Java Enum (Khuyên dùng)**
```java
// entity/enums/BookingStatus.java
public enum BookingStatus {
    PENDING("S1", "Chờ xác nhận"),
    CONFIRMED("S2", "Đã xác nhận"),
    COMPLETED("S3", "Hoàn thành"),
    CANCELLED("S4", "Đã hủy");
    
    private final String code;
    private final String description;
    
    // Constructor, getters...
}

// entity/Booking.java
@Enumerated(EnumType.STRING)
private BookingStatus status;
```

**Giải pháp 2: Giữ AllCode table (nếu cần dynamic)**
```java
@Entity
@Table(name = "allcodes")
public class AllCode {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    @Column(unique = true)
    private String keyMap;
    
    private String type;
    private String valueEn;
    private String valueVi;
}

// Trong Booking entity
@ManyToOne
@JoinColumn(name = "statusId", referencedColumnName = "keyMap")
private AllCode status;
```

**→ Đề xuất:** Dùng Enum cho ROLE, STATUS. Giữ AllCode cho TIME, PRICE, PROVINCE (có thể thay đổi)

```java
// security/JwtTokenProvider.java
@Component
public class JwtTokenProvider {
    
    @Value("${jwt.secret}")
    private String jwtSecret;
    
    @Value("${jwt.expiration}")
    private long jwtExpiration;
    
    public String generateToken(User user) {
        return Jwts.builder()
            .setSubject(user.getEmail())
            .claim("userId", user.getId())
            .claim("role", user.getRole().getKeyMap())
            .setIssuedAt(new Date())
            .setExpiration(new Date(System.currentTimeMillis() + jwtExpiration))
            .signWith(SignatureAlgorithm.HS512, jwtSecret)
            .compact();
    }
    
    public boolean validateToken(String token) {
        try {
            Jwts.parser().setSigningKey(jwtSecret).parseClaimsJws(token);
            return true;
        } catch (JwtException | IllegalArgumentException e) {
            return false;
        }
    }
}

// security/JwtAuthenticationFilter.java
@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {
    
    @Autowired
    private JwtTokenProvider tokenProvider;
    
    @Override
    protected void doFilterInternal(HttpServletRequest request, 
                                    HttpServletResponse response, 
                                    FilterChain filterChain) {
        String token = getJwtFromRequest(request);
        
        if (token != null && tokenProvider.validateToken(token)) {
            String email = tokenProvider.getEmailFromToken(token);
            UserDetails userDetails = userDetailsService.loadUserByUsername(email);
            
            UsernamePasswordAuthenticationToken authentication = 
                new UsernamePasswordAuthenticationToken(
                    userDetails, null, userDetails.getAuthorities());
            
            SecurityContextHolder.getContext().setAuthentication(authentication);
        }
        
        filterChain.doFilter(request, response);
    }
    
    private String getJwtFromRequest(HttpServletRequest request) {
        String bearerToken = request.getHeader("Authorization");
        if (bearerToken != null && bearerToken.startsWith("Bearer ")) {
            return bearerToken.substring(7);
        }
        return null;
    }
}
```

```java
        mailSender.send(message);
    }
```
